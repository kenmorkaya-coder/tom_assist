## Scope and inherited design

This is a prospective correction to `wp25-prereg-frozen/1`. It uses the same 132
authored cases and answer keys, the same eleven object families, the same five
arms, the same long/no-rot slices and domains, and the same deterministic 33-case
pilot selection (first two long cases and first no-rot case per family,
lexicographically). Case order and the modulo-five arm rotation are unchanged.
The proposed pilot remains 33 paired cases × five arms = 165 single-capture
generations. Self-report remains off.

The production path proposed for a later separately authorized pilot includes
the WP-29 corrections: authored histories are recorded in the native ledger and
committed through all five dynamics before the probe, assistant-authored turns

the pinned canonical 17-channel SICD-MSR load application and routing basis,
structural retrieval ranks in that same 8D basis, and every rendered packet item

manifest, not outcomes.

## Oracle v2 — the only comparator change

The seven-field typed action shape is unchanged. Dict key order remains
irrelevant. `cited_state_ids` and `historical_state_ids` are compared as
**multisets**: order is ignored, but membership and duplicate counts must match.
This is prospective because citation order has no semantic meaning, while a set
comparison would incorrectly hide duplicate or missing citations. Action ID,
rejected-action list, directed relationships, proposed mutations, and authority
remain exactly ordered/value-equal as in v1. SUB-E's separately registered
containment answer uses the same comparator.

The v2 oracle must identify itself as `typed-action-oracle/2`; v1 remains
available to reproduce the permanent earlier pilot. The former
`capture/lineage mismatch` taxonomy label becomes `citation-list inequality`,
which describes the measured field comparison. Prompt SHA and Response SHA mean
SHA-256 over the raw UTF-8 bytes. Cluster bootstrap metadata must retain the
SUB-D row for every `(test_id, baseline)` pair and report valid and invalid
replicate counts.

## Hypotheses and fixed analysis

H1, H0, H2, and H3 retain the exact meanings and slots in the v1 pre-registration.
All margins are unchanged:

- H1 requires SUB-D macro exact consistency at least 0.15 above both SUB-A and
  SUB-B, both paired 95% intervals strictly positive, and SUB-D at least 0.80 in
  every family.
- H0 holds when any complete-matrix H1 component does not hold; incomplete data
  are invalid rather than evidence for H0.
- H2 is evaluated only if H1 holds, using the unchanged no-rot, SUB-C, SUB-E,
  and supersession thresholds.
- H3 records a reproducible failure outside the fixed taxonomy and triggers an
  owner-review stop.

The domain-cluster bootstrap remains 10,000 resamples with seed 1729, preserving
case/arm pairs inside sampled domains and macro-averaging by family. All stop
rules, one-capture/no-retry handling, completeness requirements, raw artifact
retention, floor-only no-rot injection rule, and provider/quota boundaries from
v1 remain binding. No key, threshold, seed, arm, exclusion, or hypothesis is
changed here.
