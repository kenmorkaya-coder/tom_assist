## The Tree being tested

checkpoint and hashes frozen in the fixture. It was grown from the six-branch
scaffold by 505 accepted signed 32x32 matrix-load events. The saved preparation

## Passage loading

Each frozen teacher event is compiled to one signed, unit-Frobenius 32x32
matrix using the fixed MiniLM revision, fixed 384-to-32 projection and frozen
outer-product formula in the fixture. Parsing is out of scope. Every emitted
matrix must contain no exact-zero entry.

Passages are delivered once, in fixture order, through the actual Tree
`advance` path. The existing native low-stress wind preparation and six-angle
schedule are used unchanged. No consequence is supplied; each exposure is
closed as unobserved. For every load the runner requires:

1. the accepted state hash changes;
2. the Tree's recorded input is byte-identical to the compiled matrix;
3. every branch present before the event receives a non-zero routed matrix;
4. native fork, root-to-tip energy, force, moment and applied-matrix errors
   remain within the existing `1e-10` apparatus tolerance;
5. H/F/S memory recurrence matches the native equations and no predictor is
   trained without an outcome; and
6. a read-only route calculated immediately before delivery matches the route
   used by the accepted load to `1e-12` maximum absolute error.

The passage receipt is the actual pre-event terminal-branch local matrix set.
It is retained in memory for the run; the report keeps its digest, terminal
count and energy only.

## Query and rankings

Queries never call `advance`, never grow the Tree and never update memory.
The Tree state hash before and after all queries must be identical.

For a query and passage, the Tree score is the Frobenius cosine between the
passage's historical terminal receipt and the current query matrices at those
same branch IDs. A receipt branch that has since disappeared contributes its
passage energy but a zero query matrix; retained receipt-energy coverage is
reported. No full-corpus matrix fallback or static prototype is substituted.

Report four rankings side by side:

1. direct event-matrix cosine, as a representation reference;
2. local MiniLM cosine over the raw query and passage text;
3. actual matrix-native Tree receipt cosine; and
4. Matrix Tree + MiniLM, defined before execution as the equal mean of the two
   unit-interval transformed cosines: `0.5*((tree+1)/2) +
   0.5*((minilm+1)/2)`.

The matrix-event arm and MiniLM arm share the same frozen MiniLM encoder; this
diagnostic isolates the additional effect of matrix construction and Tree
loading, not an independent embedding-free mechanism. Ties use passage ID.

The report includes every raw score, rank, relevant rank and correct-at-1/3/5
count. There is no pass threshold, no tuning after results, no product change
and no G-gate verdict. The fixed teacher labels support only this small
contrastive diagnostic.
